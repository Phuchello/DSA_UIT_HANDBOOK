PART I

PHÂN TÍCH THUẬT TOÁN & ĐỘ PHỨC TẠP (ALGORITHM ANALYSIS)

1. Intuition (Trực giác & Động lực)

Làm sao để biết thuật toán A chạy nhanh hơn thuật toán B mà không cần phải code và chạy thử trên cùng một máy tính? Đo bằng giây (seconds) là không đáng tin cậy vì phụ thuộc vào phần cứng. Do đó, chúng ta đo lường hiệu năng bằng cách đếm số lượng "phép toán cơ bản" dựa trên kích thước dữ liệu đầu vào $n$. Đó là khởi nguồn của Ký pháp Big-O.

2. Formal Model (Định nghĩa Big-O, Big-Omega, Big-Theta)

  • $\mathcal{O}(f(n))$ (Big-O): Cận trên tiệm cận (Upper Bound). Tốc độ tăng trưởng không vượt quá $f(n)$.
  • $\Omega(f(n))$ (Big-Omega): Cận dưới tiệm cận (Lower Bound). Tốc độ tăng trưởng tối thiểu đạt $f(n)$.
  • $\Theta(f(n))$ (Big-Theta): Cận chặt tiệm cận (Tight Bound). Tốc độ tăng trưởng vừa đúng bằng bậc $f(n)$ (khi cận trên và cận dưới trùng nhau).

Thứ tự độ phức tạp từ Tốt đến Xấu: $\mathcal{O}(1) < \mathcal{O}(\log n) < \mathcal{O}(n) < \mathcal{O}(n \log n) < \mathcal{O}(n^2) < \mathcal{O}(2^n) < \mathcal{O}(n!)$

IT003 PRECISION NOTE

Phân biệt Ký pháp Tiệm cận và Kịch bản Đầu vào: Big-O, Big-Omega, Big-Theta mô tả cận toán học của hàm số, không đồng nhất với kịch bản dữ liệu đầu vào (Best/Worst/Average Case). Ví dụ: Worst-case của Insertion Sort có độ phức tạp tiệm cận chặt là $\Theta(n^2)$, trong khi Best-case của nó có độ phức tạp tiệm cận chặt là $\Theta(n)$.

4. Algorithm & Mechanics (Phân tích Vòng lặp)

Quy tắc cộng: Hai khối lệnh nối tiếp nhau $\mathcal{O}(f(n)) + \mathcal{O}(g(n)) = \mathcal{O}(\max(f(n), g(n)))$.

Quy tắc nhân: Vòng lặp lồng nhau $\mathcal{O}(f(n)) \times \mathcal{O}(g(n)) = \mathcal{O}(f(n) \cdot g(n))$.

5. C++ Educational Implementation (Phân tích Code thực tế)

// Ví dụ 1: O(n)
for (int i = 0; i < n; i++) {
    cout << i; 
}

// Ví dụ 2: O(n^2)
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        cout << i + j;
    }
}

// Ví dụ 3: O(log n)
int k = n;
while (k > 1) {
    k = k / 2;
}

6. Complexity Analysis (Phân tích Đệ quy)

Với hàm đệ quy, độ phức tạp không chỉ đếm số lệnh mà còn phụ thuộc vào Độ sâu của cây đệ quy (Recursion Tree). Ví dụ: Tính Fibonacci đệ quy $F(n) = F(n-1) + F(n-2)$ sinh ra một cây nhị phân có chiều cao $n$, dẫn đến độ phức tạp thời gian $\mathcal{O}(2^n)$ vô cùng chậm.

8. Common Errors & Pitfalls

  • Bỏ qua hằng số quá sớm: $\mathcal{O}(100n)$ và $\mathcal{O}(n)$ là giống nhau về lý thuyết, nhưng trong thực tế $100n$ chậm hơn nhiều.
  • Nhầm lẫn giữa Tốt nhất và Xấu nhất: Tìm kiếm tuyến tính có Best-case là $\Omega(1)$ nếu phần tử ở ngay đầu, nhưng Worst-case là $\mathcal{O}(n)$. Đừng nhầm lẫn!

9. Quick Recall & Exam Style

IT003 EXAM STYLE

Bẫy Đề Thi: Khi tính độ phức tạp của hàm đệ quy, sinh viên thường quên tính độ phức tạp Không gian (Space Complexity) của Call Stack. Mọi lệnh gọi đệ quy đều tốn $\mathcal{O}(1)$ bộ nhớ cho mỗi stack frame. Do đó đệ quy sâu $n$ tầng sẽ tốn $\mathcal{O}(n)$ bộ nhớ.

  • Level 0: Hàm $f(n) = 3n^2 + 5n + 10$ có Big-O là gì?
    Đáp án: $\mathcal{O}(n^2)$ (Bỏ hằng số, lấy bậc cao nhất).
  • Level 1: Vòng lặp for (int i = 0; i < n; i += 2) có độ phức tạp là bao nhiêu?
    Đáp án: Chạy $n/2$ lần $\Rightarrow \mathcal{O}(n)$.
