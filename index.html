PART I

PHÂN TÍCH THUẬT TOÁN & ĐỘ PHỨC TẠP (ALGORITHM ANALYSIS)

1. Intuition (Trực giác & Động lực)

Làm sao để biết thuật toán A chạy nhanh hơn thuật toán B mà không cần phải code và chạy thử trên cùng một máy tính? Đo bằng giây (seconds) là không đáng tin cậy vì phụ thuộc vào phần cứng. Do đó, chúng ta đo lường hiệu năng bằng cách đếm số lượng "phép toán cơ bản" dựa trên kích thước dữ liệu đầu vào $n$. Đó là khởi nguồn của Ký pháp Big-O.

2. Formal Model (Định nghĩa Big-O, Big-Omega, Big-Theta)

  • $\mathcal{O}(f(n))$ (Big-O): Cận trên tiệm cận (Upper Bound). Tốc độ tăng trưởng không vượt quá $f(n)$.
  • $\Omega(f(n))$ (Big-Omega): Cận dưới tiệm cận (Lower Bound). Tốc độ tăng trưởng tối thiểu đạt $f(n)$.
  • $\Theta(f(n))$ (Big-Theta): Cận chặt tiệm cận (Tight Bound). Tốc độ tăng trưởng vừa đúng bằng bậc $f(n)$ (khi cận trên và cận dưới trùng nhau).

Thứ tự độ phức tạp từ Tốt đến Xấu: $\mathcal{O}(1) < \mathcal{O}(\log n) < \mathcal{O}(n) < \mathcal{O}(n \log n) < \mathcal{O}(n^2) < \mathcal{O}(2^n) < \mathcal{O}(n!)$

IT003 PRECISION NOTE

Phân biệt Ký pháp Tiệm cận và Kịch bản Đầu vào: Big-O, Big-Omega, Big-Theta mô tả cận toán học của hàm số, không đồng nhất với kịch bản dữ liệu đầu vào (Best/Worst/Average Case). Ví dụ: Worst-case của Insertion Sort có độ phức tạp tiệm cận chặt là $\Theta(n^2)$, trong khi Best-case của nó có độ phức tạp tiệm cận chặt là $\Theta(n)$.

4. Algorithm & Mechanics (Phân tích Vòng lặp)

Quy tắc cộng: Hai khối lệnh nối tiếp nhau $\mathcal{O}(f(n)) + \mathcal{O}(g(n)) = \mathcal{O}(\max(f(n), g(n)))$.

Quy tắc nhân: Vòng lặp lồng nhau $\mathcal{O}(f(n)) \times \mathcal{O}(g(n)) = \mathcal{O}(f(n) \cdot g(n))$.

1. Intuition (Trực giác & Động lực)

Tìm kiếm là thao tác cơ bản nhất trong khoa học máy tính. Hãy tưởng tượng việc tìm một từ trong từ điển 1,000 trang: bạn sẽ lật từng trang từ đầu (Linear Search) hay mở đôi cuốn sách ở giữa rồi tiếp tục chia đôi (Binary Search)? Bài toán tìm kiếm quyết định hiệu năng của mọi cơ sở dữ liệu lớn.

5. C++ Educational & STL Code

// Educational Iterative Binary Search
int binarySearch(int a[], int n, int x) {
    int left = 0, right = n - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2; // Phòng tránh tràn số int
        if (a[mid] == x) return mid;
        if (a[mid] < x) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}

4. The 10 Sorting Algorithms

4.1. Selection Sort

Intuition: Tìm phần tử nhỏ nhất trong mảng chưa sắp xếp và đổi chỗ với phần tử đầu tiên của mảng đó.

void selectionSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int min_idx = i;
        for (int j = i + 1; j < n; j++)
            if (a[j] < a[min_idx]) min_idx = j;
        std::swap(a[i], a[min_idx]);
    }
}

Complexity: $\Theta(n^2)$ cho mọi trường hợp. Stability: No.

4.2. Interchange Sort

Intuition: So sánh cặp $(i, j)$, nếu sai thứ tự thì đổi chỗ ngay lập tức.

void interchangeSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++)
        for (int j = i + 1; j < n; j++)
            if (a[i] > a[j]) std::swap(a[i], a[j]);
}

Complexity: $\Theta(n^2)$. Stability: No.

Bước iMảngThao tác
0[3, 2, 1]swap(3,2) → [2,3,1], swap(2,1) → [1,3,2]

4.3. Bubble Sort

Intuition: Nổi bọt, đẩy phần tử lớn nhất xuống cuối mảng qua từng lượt.

void bubbleSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {
        bool swapped = false;
        for (int j = 0; j < n - i - 1; j++)
            if (a[j] > a[j+1]) { std::swap(a[j], a[j+1]); swapped = true; }
        if (!swapped) break;
    }
}

Complexity: Best $\Theta(n)$, Worst $\Theta(n^2)$. Stability: Yes.

Bước iMảngThao tác
0[3, 2, 1]swap(3,2), swap(3,1) → [2, 1, 3]

4.4. Insertion Sort

Intuition: Chèn từng phần tử vào vị trí thích hợp trong mảng đã sắp xếp ở phía trước.

void insertionSort(int a[], int n) {
    for (int i = 1; i < n; i++) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }
        a[j + 1] = key;
    }
}

Complexity: Best $\Theta(n)$, Worst $\Theta(n^2)$. Stability: Yes.

Bước iMảngThao tác

4.5. Binary Insertion Sort

Intuition: Cải tiến Insertion Sort bằng cách dùng tìm kiếm nhị phân để tìm vị trí chèn.

void binaryInsertionSort(int a[], int n) {
    for (int i = 1; i < n; i++) {
        int key = a[i], left = 0, right = i - 1;
        while (left <= right) {
            int mid = (left + right) / 2;
            if (a[mid] > key) right = mid - 1;
            else left = mid + 1;
        }
        for (int j = i - 1; j >= left; j--) a[j + 1] = a[j];
        a[left] = key;
    }
}

Complexity: $\Theta(n^2)$. Stability: Yes.

4.6. Shell Sort

Intuition: Sắp xếp các phần tử cách nhau một khoảng gap, sau đó giảm dần gap.

void shellSort(int a[], int n) {
    for (int gap = n/2; gap > 0; gap /= 2) {
        for (int i = gap; i < n; i++) {
            int temp = a[i], j;
            for (j = i; j >= gap && a[j - gap] > temp; j -= gap)
                a[j] = a[j - gap];
            a[j] = temp;
        }
    }
}

Complexity: Phụ thuộc gap. Stability: No.

4.7. Heap Sort

Intuition: Xây dựng Max-Heap rồi liên tục lấy phần tử lớn nhất đẩy về cuối.

void heapify(int a[], int n, int i) {
    int largest = i, l = 2*i + 1, r = 2*i + 2;
    if (l < n && a[l] > a[largest]) largest = l;
    if (r < n && a[r] > a[largest]) largest = r;
    if (largest != i) { std::swap(a[i], a[largest]); heapify(a, n, largest); }
}
void heapSort(int a[], int n) {
    for (int i = n / 2 - 1; i >= 0; i--) heapify(a, n, i);
    for (int i = n - 1; i > 0; i--) { std::swap(a[0], a[i]); heapify(a, i, 0); }
}

4.8. Merge Sort

Intuition: Chia để trị, chia mảng thành 2 nửa, sắp xếp rồi trộn lại.

// Pseudocode Helper: void merge(int a[], int l, int m, int r);
void mergeSort(int a[], int l, int r) {
    if (l < r) {
        int m = l + (r - l) / 2;
        mergeSort(a, l, m); mergeSort(a, m + 1, r);
        merge(a, l, m, r); // Hàm trộn
    }
}

PART IV

DANH SÁCH LIÊN KẾT (LINKED LIST)

1. Intuition (Trực giác & Động lực)

Mảng tĩnh có kích thước cố định và thao tác chèn/xóa ở giữa tốn $\mathcal{O}(n)$ do phải dời hàng loạt phần tử. Danh sách liên kết (Linked List) giải quyết triệt để vấn đề này bằng cách cấp phát động từng nút (Node) nằm rải rác trên bộ nhớ Heap và liên kết chúng bằng các con trỏ (Pointer).

2. Formal Model (Định nghĩa Cấu trúc)

Một Singly Linked List gồm tập hợp các nút Node, trong đó mỗi nút chứa 2 thành phần: data (giá trị lưu trữ) và pNext (con trỏ chỉ tới nút kế tiếp). Danh sách được quản lý bởi con trỏ pHead (chỉ nút đầu) và pTail (chỉ nút cuối).

3. Visual Diagram (Sơ đồ Bộ nhớ Danh sách Liên kết)

4. Algorithm & Mechanics (Các Thao tác Con trỏ)

  • Add Head: Tạo pNew. Cho pNew->pNext = pHead. Cập nhật pHead = pNew.
  • Add Tail: Tạo pNew. Cho pTail->pNext = pNew. Cập nhật pTail = pNew.
  • Delete Head: Lưu temp = pHead. Cho pHead = pHead->pNext. Giải phóng delete temp.
  • Search: Duyệt từ đầu, nếu p->data == val thì trả về p.
  • Insert After: Tìm nút q. Tạo pNew, pNew->pNext = q->pNext, q->pNext = pNew.
  • Count: Duyệt qua danh sách và tăng biến đếm.

5. C++ Educational & STL Code

5.1 Singly Linked List

struct Node {
    int data;
    Node* pNext;
};
struct LinkedList {
    Node* pHead;
    Node* pTail;
};
void addHead(LinkedList& list, int val) {
    Node* p = new Node{val, nullptr};
    if (!list.pHead) list.pHead = list.pTail = p;
    else { p->pNext = list.pHead; list.pHead = p; }
}
void deleteHead(LinkedList& list) {
    if (!list.pHead) return;
    Node* temp = list.pHead;
    list.pHead = list.pHead->pNext;
    if (!list.pHead) list.pTail = nullptr;
    delete temp;
}
Node* search(LinkedList list, int val) {
    for (Node* p = list.pHead; p != nullptr; p = p->pNext)
        if (p->data == val) return p;
    return nullptr;
}
void insertAfter(LinkedList& list, Node* q, int val) {
    if (!q) return;
    Node* p = new Node{val, q->pNext};
    q->pNext = p;
    if (list.pTail == q) list.pTail = p;
}
int countNodes(LinkedList list) {
    int count = 0;
    for (Node* p = list.pHead; p != nullptr; p = p->pNext) count++;
    return count;
}

NGĂN XẾP VÀ HÀNG ĐỢI (STACK & QUEUE)

1. Intuition (Trực giác & Động lực)

Stack (Ngăn xếp) giống như một chồng dĩa: dĩa nào đặt vào sau cùng sẽ được lấy ra đầu tiên (LIFO — Last In, First Out). Queue (Hàng đợi) giống như hàng người xếp hàng mua vé: ai đến trước sẽ được phục vụ trước (FIFO — First In, First Out).

2. Formal Model (Định nghĩa Cấu trúc)

  • Stack ADT: Các thao tác chính gồm push(x) (thêm vào đỉnh), pop() (lấy khỏi đỉnh), top() (xem đỉnh), isEmpty().
  • Queue ADT: Các thao tác chính gồm enqueue(x) (thêm vào đuôi), dequeue() (lấy khỏi đầu), front() (xem đầu), isEmpty().

3. Visual Diagram (Sơ đồ Tràn Ảo & Hàng Đợi Vòng)

4. Applications & Algorithms

4.1 Hiện tượng Tràn Ảo - False Overflow

// Array Stack
const int MAX = 100;
struct ArrayStack {
    int top_idx = -1;
    int a[MAX];
    void push(int x) { if (top_idx < MAX-1) a[++top_idx] = x; }
    int pop() { 
        if (top_idx < 0) return -1; // Underflow check
        return a[top_idx--]; 
    }
};

// Circular Queue Implementation
struct CircularQueue {
    int front = 0, rear = -1, count = 0;
    int a[MAX];
    void enqueue(int x) {
        if (count == MAX) return; // Overflow check
        rear = (rear + 1) % MAX;
        a[rear] = x; count++;
    }
    int dequeue() {
        if (count == 0) return -1; // Underflow check
        int val = a[front];
        front = (front + 1) % MAX;
        count--;
        return val;
    }
};

PART VI

CÂY VÀ CÂY NHỊ PHÂN (TREES & BINARY TREES)

1. Intuition (Trực giác & Động lực)

Khác với mảng hay danh sách liên kết là cấu trúc dữ liệu tuyến tính (Linear), Cây (Tree) là cấu trúc dữ liệu phi tuyến (Non-linear) phân cấp. Cây mô phỏng hoàn hảo các hệ thống phân cấp thực tế như cây thư mục máy tính, sơ đồ tổ chức công ty hay cây quyết định.

2. Formal Model & Terminology (Định nghĩa & Thuật ngữ)

  • Root (Gốc): Nút duy nhất không có nút cha.
  • Leaf (Nút lá): Nút không có con nào (bậc của nút bằng 0).
  • Degree (Bậc): Số nút con của một nút.
  • IT003 CONVENTION Level (Mức): Nút gốc Root nằm ở Level 0. Nút con của Root nằm ở Level 1. Chiều cao của cây $H = \text{max\_level} + 1$.

3. Visual Diagram (Sơ đồ Duyệt Cây Nhị Phân)

4. Algorithm & Mechanics (3 Phép Duyệt Cây)

  • NLR (Pre-order / Tiền tự): Thăm Nút gốc $N \Rightarrow $ Duyệt Cây con trái $L \Rightarrow $ Duyệt Cây con phải $R$.
  • LNR (In-order / Trung tự): Duyệt Cây con trái $L \Rightarrow $ Thăm Nút gốc $N \Rightarrow $ Duyệt Cây con phải $R$.
  • LRN (Post-order / Hậu tự): Duyệt Cây con trái $L \Rightarrow $ Duyệt Cây con phải $\Rightarrow $ Thăm Nút gốc $N$.

5. C++ Educational & Traversals Code

PART VII

CÂY NHỊ PHÂN TÌM KIẾM (BINARY SEARCH TREE - BST)

1. Intuition (Trực giác & Động lực)

Mảng sắp xếp cho phép Tìm kiếm Nhị phân $\mathcal{O}(\log n)$ nhưng chèn/xóa tốn $\mathcal{O}(n)$. Danh sách liên kết cho phép chèn/xóa $\mathcal{O}(1)$ nhưng tìm kiếm tốn $\mathcal{O}(n)$. Với Binary Search Tree (BST), Tìm kiếm, Chèn và Xóa đều là $\mathcal{O}(h)$ theo chiều cao cây: trung bình $\mathcal{O}(\log n)$ khi cây cân đối, nhưng Worst Case $\mathcal{O}(n)$ khi cây lệch.

2. Formal Model & Invariants (Định nghĩa & Bất biến)

BST là cây nhị phân thỏa mãn tính chất bất biến tại mọi nút $X$:

  • Mọi khóa ở cây con trái của $X$ đều nhỏ hơn khóa của $X$ ($\text{key}(Left) < \text{key}(X)$).
  • Mọi khóa ở cây con phải của $X$ đều lớn hơn khóa của $X$ ($\text{key}(Right) > \text{key}(X)$).

3. Visual Diagram (Sơ đồ Xóa Nút BST 2 Con)

4. Algorithm & Mechanics (Các thao tác cơ bản)

  • Tìm kiếm (Search): Duyệt từ gốc, nhỏ sang trái, lớn sang phải. $\mathcal{O}(h)$; cây cân đối là $\mathcal{O}(\log n)$, cây lệch có thể là $\mathcal{O}(n)$.
  • Thêm (Insert): Tương tự tìm kiếm để tìm vị trí nút lá thích hợp rồi chèn.
  • Min/Max: Min nằm ở nút cực trái, Max nằm ở nút cực phải.
  • Duyệt cây (Traversals):
    • Pre-order (NLR): Root $\rightarrow$ Left $\rightarrow$ Right
    • In-order (LNR): Left $\rightarrow$ Root $\rightarrow$ Right (In ra mảng tăng dần)
    • Post-order (LRN): Left $\rightarrow$ Right $\rightarrow$ Root
  • Xóa (Delete) - 3 Trường hợp:
    • Nút lá: Xóa trực tiếp nút.

TreeNode* deleteNode(TreeNode* root, int key) {
    if (root == nullptr) return root;

    if (key < root->data) root->pLeft = deleteNode(root->pLeft, key);
    else if (key > root->data) root->pRight = deleteNode(root->pRight, key);
    else {
        if (root->pLeft == nullptr) {
            TreeNode* temp = root->pRight;
            delete root; return temp;
        } else if (root->pRight == nullptr) {
            TreeNode* temp = root->pLeft;
            delete root; return temp;
        }
        TreeNode* temp = findMin(root->pRight); // Min Right
        root->data = temp->data;
        root->pRight = deleteNode(root->pRight, temp->data);
    }
    return root;
}

PART VIII

CÂY CÂN BẰNG AVL (AVL TREES)

1. Intuition (Trực giác & Động lực)

Để khắc phục nhược điểm bị suy biến thành $\mathcal{O}(n)$ của BST thông thường, Adelson-Velsky và Landis (AVL) đã đề xuất cây BST tự cân bằng: tự động thực hiện phép Xoay (Rotation) mỗi khi độ lệch chiều cao giữa 2 cây con vượt quá 1.

2. Formal Model & Balance Factor

Chỉ số cân bằng của nút $X$:

$$BF(X) = h_{left} - h_{right}$$

Điều kiện AVL: $BF(X) \in \{-1, 0, +1\}$ với mọi nút $X$. Nếu $|BF(X)| \ge 2$, cây bị mất cân bằng tại $X$.

3. Visual Diagram (Cơ chế Xoay Đơn Phải - Right Rotation)

4. Algorithm & Mechanics (Xoay Đơn Phải Rotate Right)

Cho nút $Y$ bị mất cân bằng nghiêng trái ($BF = +2$), nút con trái là $X$. Phép xoay phải đưa $X$ lên làm cha $Y$, và chuyển cây con phải của $X$ ($T_2$) sang làm cây con trái của $Y$.

Tại sao phép xoay bảo toàn tính chất BST?
Theo tính chất BST ban đầu: A < X < T2 < Y < C. Khi xoay phải, $X$ trở thành gốc mới, $Y$ trở thành con phải của $X$. Nút $T2$ (lớn hơn $X$ nhưng nhỏ hơn $Y$) được chuyển một cách hoàn toàn tự nhiên từ con phải của $X$ sang làm con trái của $Y$, vẫn thỏa mãn chặt chẽ bất biến BST.

5. C++ Educational Implementation

#include <algorithm>

struct AVLNode {
    int key;
    int height;
    AVLNode* left;
    AVLNode* right;
};

int getHeight(AVLNode* n) { return n == nullptr ? 0 : n->height; }
int getBalance(AVLNode* n) { return n == nullptr ? 0 : getHeight(n->left) - getHeight(n->right); }

AVLNode* rotateRight(AVLNode* y) {
    AVLNode* x = y->left;
    AVLNode* T2 = x->right;
    x->right = y;
    y->left = T2;
    y->height = std::max(getHeight(y->left), getHeight(y->right)) + 1;
    x->height = std::max(getHeight(x->left), getHeight(x->right)) + 1;
    return x;
}

AVLNode* rotateLeft(AVLNode* x) {
    AVLNode* y = x->right;
    AVLNode* T2 = y->left;
    y->left = x;
    x->right = T2;
    x->height = std::max(getHeight(x->left), getHeight(x->right)) + 1;
    y->height = std::max(getHeight(y->left), getHeight(y->right)) + 1;
    return y;
}

AVLNode* insertAVL(AVLNode* node, int key) {
    if (node == nullptr) return new AVLNode{key, 1, nullptr, nullptr};
    if (key < node->key) node->left = insertAVL(node->left, key);
    else if (key > node->key) node->right = insertAVL(node->right, key);
    else return node;

    node->height = 1 + std::max(getHeight(node->left), getHeight(node->right));
    int balance = getBalance(node);

    // LL Case
    if (balance > 1 && key < node->left->key) return rotateRight(node);
    // RR Case
    if (balance < -1 && key > node->right->key) return rotateLeft(node);
    // LR Case
    if (balance > 1 && key > node->left->key) {
        node->left = rotateLeft(node->left);
        return rotateRight(node);
    }
    // RL Case
    if (balance < -1 && key < node->right->key) {
        node->right = rotateRight(node->right);
        return rotateLeft(node);
    }
    return node;
}

PART IX

HEAPS VÀ HÀNG ĐỢI ƯU TIÊN (HEAP & PRIORITY QUEUE)

1. Intuition (Trực giác & Động lực)

Hàng đợi ưu tiên (Priority Queue) là hàng đợi mà phần tử có độ ưu tiên cao nhất luôn được phục vụ trước. Cấu trúc dữ liệu Heap biểu diễn hoàn hảo hàng đợi ưu tiên nhờ khả năng tìm phần tử cực đại/cực tiểu trong $\mathcal{O}(1)$ và cập nhật lại cây trong $\mathcal{O}(\log n)$.

2. Formal Model & Invariants

Max-Heap là Cây nhị phân hoàn chỉnh (Complete Binary Tree) thỏa mãn bất biến: Khóa của nút cha luôn $\ge$ khóa của các nút con.

3. Visual Diagram (Biểu diễn Heap bằng Mảng)

4. Algorithm & Mechanics (Công thức Chỉ số Mảng)

IT003 CONVENTION: Với mảng bắt đầu từ index 0:

  • $\text{parent}(i) = \lfloor (i - 1) / 2 \rfloor$
  • $\text{left}(i) = 2i + 1$
  • $\text{right}(i) = 2i + 2$

5. C++ Educational & STL Implementation

#include <algorithm>
#include <queue>

void heapify(int a[], int n, int i) {
    int largest = i;
    int left = 2 * i + 1, right = 2 * i + 2;
    if (left < n && a[left] > a[largest]) largest = left;
    if (right < n && a[right] > a[largest]) largest = right;
    if (largest != i) {
        std::swap(a[i], a[largest]);
        heapify(a, n, largest);
    }
}

// C++ STL Priority Queue
void stlPriorityQueue() {
    std::priority_queue<int> maxHeap; // Max Heap mặc định
    maxHeap.push(50); maxHeap.push(80);
    int topVal = maxHeap.top(); // 80
}

6. Complexity Analysis

Tìm Max: $\Theta(1)$. Chèn / Xóa Max (Heapify): $\Theta(\log n)$. Thuật toán buildHeap tạo Heap từ mảng ngẫu nhiên đạt độ phức tạp tuyến tính $\Theta(n)$.

Giải thích trực giác vì sao buildHeap là $\Theta(n)$: Hầu hết các nút nằm ở đáy cây (mức lá). Lá không cần heapify (chiều cao $h=0$). Chỉ có một vài nút ở đỉnh cây mới cần rớt xuống sâu. Tổng số thao tác rớt của tất cả các nút tạo thành một chuỗi giảm dần hội tụ về $\Theta(n)$. Heap Sort (Build Heap + Extract Max liên tục) đạt $\Theta(n \log n)$.

CÂY B-TREE (B-TREES - MULTI-WAY SEARCH TREES)

1. Intuition (Trực giác & Động lực)

Khi dữ liệu quá lớn không thể chứa hết trong RAM mà phải lưu trên đĩa cứng (Hard Drive / SSD), mỗi lần đọc đĩa (Disk I/O) tốn thời gian rất lớn. B-Tree (Cây tìm kiếm đa đường) làm giảm chiều cao của cây bằng cách cho phép mỗi nút chứa nhiều khóa và nhiều con, tối ưu hóa tối đa số lần đọc đĩa.

2. Formal Model & Rules (Quy tắc B-Tree Bậc $m=5$)

IT003 CONVENTION: B-Tree bậc 5 ($m=5$) xuất hiện phổ biến trong các bộ đề IT003 đã phân tích với các quy chuẩn:

  • Số khóa tối đa trong 1 nút: $m - 1 = 4$ khóa.
  • Số con tối đa của 1 nút: $m = 5$ con.
  • Số khóa tối thiểu (nút không phải gốc): $\lceil m/2 \rceil - 1 = \lceil 2.5 \rceil - 1 = 2$ khóa.
  • Số con tối thiểu (nút không phải gốc): $\lceil m/2 \rceil = 3$ con.
  • Tất cả các nút lá đều nằm trên cùng một mức.

3. Visual Diagram (Sơ đồ Tách Nút B-Tree Bậc 5)

4. Algorithm & Mechanics (Tách Nút và Xóa Nút)

Thêm (Insert) & Tách Nút (Split)

Khi chèn vào nút đã có 4 khóa làm xuất hiện khóa thứ 5 ($[k_1, k_2, k_3, k_4, k_5]$): Khóa trung vị $k_3$ được đẩy nổi (Promote) lên nút cha. Nút bị Tách (Split) thành 2 nút con chứa $[k_1, k_2]$ và $[k_4, k_5]$.

Xóa (Delete) trên B-Tree bậc 5 (m=5)

  • Trường hợp 1: Xóa ở nút lá và $\ge$ min keys (Số khóa $\ge 2$): Xóa trực tiếp, không vi phạm cấu trúc.
  • Trường hợp 2: Xóa gây Underflow (Số khóa tụt xuống 1):
    • Mượn (Borrow / Redistribution): Nếu anh em ruột kề cạnh có $> 2$ khóa, mượn 1 khóa thông qua nút cha. Khóa của anh em lên cha, khóa của cha rớt xuống nút hiện tại.
    • Gộp (Merge): Nếu anh em kề cạnh chỉ có đúng $2$ khóa, tiến hành gộp nút hiện tại, nút anh em và 1 khóa từ cha lại thành 1 nút (tổng cộng $1 + 2 + 1 = 4$ khóa).
  • Xóa ở nút trong (Internal Node): Thay thế bằng phần tử tiền nhiệm (Max Left) hoặc kế nhiệm (Min Right) ở nút lá, sau đó tiến hành xóa ở nút lá đó.
  • Trường hợp Đặc biệt (Root): Nếu gốc sau khi Merge bị mất hết khóa (chỉ còn 1 con), nút con đó sẽ trở thành Root mới. Chiều cao cây giảm đi 1.

PART XI

BẢNG BĂM (HASH TABLE)

1. Intuition (Trực giác & Động lực)

Bạn có muốn tìm kiếm dữ liệu trong thời gian tức thì $\mathcal{O}(1)$ không? Bảng băm (Hash Table) biến khóa $k$ thành chỉ số mảng thông qua Hàm Băm (Hash Function), cho phép truy xuất dữ liệu gần như ngay lập tức.

2. Formal Model & Collision Resolution

Hàm băm modulo: $h(k) = k \bmod M$ ($M$ là kích thước bảng băm). Đụng độ (Collision) xảy ra khi 2 khóa khác nhau có cùng giá trị băm. Các phương pháp giải quyết đụng độ chuẩn IT003:

  • Linear Probing (Dò tuyến tính): $h(k, i) = (h(k) + i) \bmod M$
  • Quadratic Probing (Dò bậc hai): $h(k, i) = (h(k) + i^2) \bmod M$
  • Double Hashing (Băm kép): $h(k, i) = (h_1(k) + i \cdot h_2(k)) \bmod M$ (trong đó $h_2(k)$ là hàm băm thứ hai bắt buộc tuân theo đề bài cho; ví dụ phổ biến: $h_2(k) = R - (k \bmod R)$).
  • Separate Chaining: Lưu mỗi ô bằng một Danh sách liên kết đơn.

3. Visual Diagram (Sơ đồ Dò Tuyến Tính Hash Probing)

4. Algorithm & Mechanics (Đếm So Sánh $C_{\text{succ}}$ và $C_{\text{unsucc}}$)

IT003 CONVENTION:

  • Tìm kiếm Thành công ($C_{\text{succ}}$): Trung bình số phép so sánh để tìm thấy các khóa đang có trong bảng.
  • Tìm kiếm Thất bại ($C_{\text{unsucc}}$): Trung bình số phép so sánh xuất phát từ mỗi vị trí $i \in [0, M-1]$, lặp theo đúng chuỗi dò thực tế của phương pháp tương ứng (Linear / Quadratic / Double Hashing) cho đến khi gặp ô trống (EMPTY) đầu tiên. Ô bị xóa (DELETED) không dừng chuỗi dò!

ĐỒ THỊ VÀ BIỂU DIỄN ĐỒ THỊ (GRAPHS & REPRESENTATIONS)

1. Intuition (Trực giác & Động lực)

Đồ thị (Graph) là mô hình tổng quát nhất biểu diễn các mối quan hệ liên kết: mạng xã hội (user là đỉnh, bạn bè là cạnh), bản đồ giao thông (giao lộ là đỉnh, đường đi là cạnh), hay mạng máy tính.

2. Formal Model & Definitions

Đồ thị $G = (V, E)$ gồm tập đỉnh $V$ ($|V| = n$) và tập cạnh $E$ ($|E| = m$).

  • Phân loại: Vô hướng (Undirected) / Có hướng (Directed), Có trọng số (Weighted) / Không trọng số.
  • Bậc (Degree): Đối với đồ thị vô hướng, $deg(v)$ là số cạnh nối với đỉnh $v$. Với đồ thị có hướng, chia làm Bán bậc vào (Indegree) $deg^-(v)$ (số cạnh đi vào) và Bán bậc ra (Outdegree) $deg^+(v)$ (số cạnh đi ra).
  • Thành phần liên thông (Connected Components): Một đồ thị vô hướng là liên thông nếu có đường đi giữa mọi cặp đỉnh. Nếu không, nó phân rã thành nhiều thành phần liên thông. Đối với đồ thị có hướng, ta xét Liên thông mạnh (Strongly Connected) và Liên thông yếu.

4. Algorithm & Mechanics (Chuyển đổi Biểu diễn)

Chuyển đổi từ Ma trận kề $A[V][V]$ sang Danh sách kề: Duyệt qua từng hàng $i \in [0, V-1]$, nếu $A[i][j] \neq 0$ thì thêm $j$ vào danh sách adj[i].

PART XIII

DUYỆT ĐỒ THỊ (BFS & DFS TRAVERSALS)

1. Intuition (Trực giác & Động lực)

Duyệt đồ thị là quá trình ghé thăm hệ thống tất cả các đỉnh của đồ thị. BFS (Chiều rộng) loang dần theo từng lớp khoảng cách từ đỉnh xuất phát (dùng Queue). DFS (Chiều sâu) đi sâu nhất có thể theo một nhánh trước khi quay lùi (Backtrack) (dùng Stack hoặc Đệ quy).

2. Formal Model & Algorithms

  • BFS Algorithm: Khởi tạo queue Q, đánh dấu visited[start] = true. Lặp khi Q không rỗng: lấy u = Q.front(), thăm u, với mỗi v kề u chưa ghé thăm: đánh dấu visited[v] = true và Q.push(v).
  • DFS Algorithm: Đánh dấu visited[u] = true. Với mỗi v kề u chưa ghé thăm: gọi đệ quy DFS(v).
  • Xử lý đồ thị không liên thông: Cần một vòng lặp ngoài duyệt qua toàn bộ $V$ đỉnh. Nếu !visited[i] thì gọi BFS(i) hoặc DFS(i).

3. Visual Diagram (Mô tả Loang BFS vs Đi sâu DFS)

4. C++ Implementation (BFS & DFS)

#include <vector>
#include <queue>
#include <iostream>
#include <functional>
#include <utility>

void BFS(int start, const std::vector<std::vector<int>>& adj, int V) {
    std::vector<bool> visited(V, false);
    std::queue<int> q;
    visited[start] = true; q.push(start);

    while (!q.empty()) {
        int u = q.front(); q.pop();
        std::cout << u << " ";
        for (int v : adj[u]) {
            if (!visited[v]) {
                visited[v] = true;
                q.push(v);
            }
        }
    }
}

void DFSUtil(int u, const std::vector<std::vector<int>>& adj, std::vector<bool>& visited) {
    visited[u] = true;
    std::cout << u << " ";
    for (int v : adj[u]) {
        if (!visited[v]) DFSUtil(v, adj, visited);
    }
}

THUẬT TOÁN ĐƯỜNG ĐI NGẮN NHẤT (SHORTEST PATH - DIJKSTRA)

1. Intuition (Trực giác & Động lực)

Bài toán tìm đường đi ngắn nhất giữa 2 địa điểm trên bản đồ Google Maps là ứng dụng thực tế phổ biến nhất của thuật toán Dijkstra. Thuật toán hoạt động theo nguyên lý tham ăn (Greedy): luôn chọn đỉnh có khoảng cách tạm thời nhỏ nhất để cố định (Fix/Finalize) đường đi ngắn nhất tới đỉnh đó.

2. Formal Model & Relaxation Principle

Điều kiện tiên quyết: Đồ thị có trọng số không âm ($w(e) \ge 0$). Thao tác Nới cạnh (Relaxation) giữa cạnh $(u, v)$ có trọng số $w$:

$$\text{If } d[u] + w < d[v] \Rightarrow d[v] = d[u] + w, \quad p[v] = u$$

3. Visual Diagram (Sơ đồ Nới Cạnh Relaxation)

4. C++ Implementation (Dijkstra using Priority Queue)

#include <vector>
#include <queue>
#include <iostream>
#include <functional>
#include <utility>

const int INF = 1e9;
using pii = std::pair<int, int>; // (d[u], u)

void dijkstra(int start, const std::vector<std::vector<pii>>& adj, int V) {
    std::vector<int> d(V, INF);
    std::priority_queue<pii, std::vector<pii>, std::greater<pii>> pq;

    d[start] = 0;
    pq.push({0, start});

    while (!pq.empty()) {
        auto [dist, u] = pq.top(); pq.pop();
        if (dist > d[u]) continue;

        for (auto& edge : adj[u]) {
            int v = edge.first, w = edge.second;
            if (d[u] + w < d[v]) {
                d[v] = d[u] + w;
                pq.push({d[v], v});
            }
        }
    }
}

5. Algorithms & Complexity Analysis Comparison

Bên cạnh Dijkstra, ta có các thuật toán khác để xử lý đồ thị có trọng số âm hoặc tìm đường đi ngắn nhất mọi cặp đỉnh:

  • Bellman-Ford: Lặp nới lỏng toàn bộ $E$ cạnh đúng $V-1$ lần, rồi kiểm tra thêm một lượt để phát hiện chu trình âm có thể đi tới từ nguồn. Độ phức tạp: $\Theta(V \times E)$.
  • Floyd-Warshall (All-Pairs): Dùng Quy hoạch động, $D[i][j] = \min(D[i][j], D[i][k] + D[k][j])$. Cho phép cạnh có trọng số âm, nhưng nếu đồ thị chứa chu trình âm (Negative Cycle) thì khái niệm đường đi ngắn nhất hữu hạn không còn hợp lệ. Độ phức tạp: $\Theta(V^3)$.

1. Quick Recall Cheat Sheet (Tóm Tắt Nhanh Ôn Thi)

⚡ Master Summary Cheat Sheet
  • Selection & Interchange Sort: Phép so sánh luôn cố định $C = \frac{n(n-1)}{2}$. Interchange Sort là thuật toán đặc thù UIT.
  • Binary Search: Bắt buộc mảng đã sắp xếp. $\Theta(\log n)$ thời gian.
  • BST Deletion (2 con): Đọc kỹ đề dùng Max-Left hay Min-Right làm phần tử thế mạng.
  • AVL Rotation: $BF = h_{left} - h_{right}$. $+2$ nghiêng trái (LL/LR), $-2$ nghiêng phải (RR/RL).
  • B-Tree Bậc 5 ($m=5$): Max 4 keys, Min 2 keys per node. Tràn 5 keys $\Rightarrow$ Tách nút đẩy nổi khóa thứ 3 (trung vị) lên cha.
  • Hash Probing Unsuccessful Search: Phải dò tới khi gặp ô EMPTY đầu tiên. Ô DELETED không dừng!
  • BFS / DFS: BFS dùng Queue loang theo lớp; DFS dùng Stack/Đệ quy đi sâu. Tùy thuộc vào thứ tự đỉnh kề.
  • Dijkstra: Chỉ áp dụng cho trọng số không âm ($w \ge 0$). Nới cạnh: if (d[u] + w < d[v]) d[v] = d[u] + w.

2. Phương pháp Ôn thi IT003 Hiệu quả

Một tỷ lệ đáng kể câu hỏi trong các đề thi IT003 đã phân tích yêu cầu sinh viên phải chạy vết (trace) thủ công, vẽ lại trạng thái cấu trúc dữ liệu sau mỗi bước, hoặc suy luận độ phức tạp dựa trên convention đặc thù. Học thuộc lòng code mà không hiểu cơ chế chạy tay sẽ mất điểm phần lớn các câu tự luận.

3. Integrated Practice Bank (Hệ thống Bài tập 5 Level)

Chủ đề 1: Sorting Algorithms (Thuật toán Sắp xếp)

  • Level 0 (Concept): Thuật toán sắp xếp nào có Best Case là $\Theta(n)$ khi mảng đã có thứ tự? (Đáp án: Bubble Sort tối ưu, Insertion Sort).
  • Level 1 (Mini Trace): Cho mảng $A = [8, 4, 2]$. Chạy tay 1 lượt thuật toán Bubble Sort. (Đáp án: [4, 2, 8]).
  • Level 2 (Full Trace): Chạy tay toàn bộ thuật toán Selection Sort trên mảng $[29, 10, 14, 37, 14]$. Xác định tính ổn định.
  • Level 3 (Code): Viết hàm void QuickSort(int a[], int left, int right) dùng phân hoạch Lomuto.
  • Level 4 (Exam Style): Tính số phép so sánh và số phép gán của Interchange Sort trên mảng $[5, 4, 3, 2, 1]$.
  • Level 5 (Challenge): Cải tiến Bubble Sort để dừng sớm nếu không có bất kỳ lần đổi chỗ nào xảy ra trong 1 lượt. Viết code C++ và chứng minh Best Case $\Theta(n)$.

Chủ đề 2: Cây (BST, AVL, B-Tree, Heap)

  • Level 0 (Concept): Chiều cao tối đa của cây AVL chứa $N$ nút được chặn trên bởi hàm gì? (Đáp án: $\mathcal{O}(\log N)$).
  • Level 1 (Mini Trace): Cho Max-Heap dạng mảng [50, 30, 40, 10, 20]. Nút lá bắt đầu từ index nào?
  • Level 2 (Full Trace): Lần lượt chèn $10, 20, 30, 40, 50$ vào B-Tree bậc 5 rỗng. Vẽ cây ở bước tách nút.
  • Level 3 (Code): Viết hàm tìm node có giá trị lớn nhất (Max) trong BST.
  • Level 4 (Exam Style): Chèn lần lượt $30, 20, 40, 10, 5$ vào cây AVL. Trình bày chi tiết hệ số cân bằng (BF) tại bước gây mất cân bằng và vẽ cây sau khi Xoay LL.
  • Level 5 (Challenge): Cho cây BST bị mất 1 nhánh, dùng mảng duyệt LNR (In-order) và NLR (Pre-order) để phục hồi lại chính xác hình dáng cây BST ban đầu.

Chủ đề 3: Hash Table (Bảng Băm)

  • Level 0 (Concept): Linear Probing gặp hiện tượng gì làm giảm hiệu suất? (Đáp án: Primary Clustering - Cụm sơ cấp).
  • Level 1 (Mini Trace): Hàm băm $h(k) = k \bmod 7$. Khóa $15$ bị đụng độ tại ô $1$. Dùng Quadratic Probing $i^2$, lần dò tiếp theo là ô nào? (Đáp án: $(1 + 1^2) \bmod 7 = 2$).
  • Level 2 (Full Trace): Băm các khóa $43, 23, 1, 0, 15, 31$ vào bảng băm $M=10$, dùng Double Hashing với $h_1(k) = k \bmod 10$, $h_2(k) = 7 - (k \bmod 7)$. Vẽ bảng băm cuối cùng.
  • Level 3 (Code): Khai báo cấu trúc dữ liệu cho Bảng băm dùng Phương pháp Nối kết trực tiếp (Separate Chaining).
  • Level 4 (Exam Style): Tính số phép so sánh trung bình tìm kiếm thành công ($C_{succ}$) và không thành công ($C_{unsucc}$) cho Bảng băm Linear Probing kích thước 7 chứa 4 phần tử.
  • Level 5 (Challenge): Cài đặt hàm Delete cho Linear Probing sử dụng cờ DELETED (Tombstone) để không làm đứt mạch dò tìm.

Chủ đề 4: Graph & Shortest Path (Đồ thị & Đường đi)

  • Level 0 (Concept): Đồ thị vô hướng có $V$ đỉnh và $E$ cạnh. Tổng bậc của tất cả các đỉnh bằng bao nhiêu? (Đáp án: $2E$ - Định lý Bắt tay).
  • Level 1 (Mini Trace): Viết thứ tự duyệt BFS bắt đầu từ đỉnh 0, biết đỉnh 0 kề với {1, 3, 2} (duyệt theo thứ tự đỉnh tăng dần). (Đáp án: 0, 1, 2, 3).
  • Level 2 (Full Trace): Chạy tay thuật toán Dijkstra tìm đường đi ngắn nhất từ đỉnh A đến tất cả các đỉnh còn lại trên một đồ thị 5 đỉnh cho trước.
  • Level 3 (Code): Viết hàm tính Bậc vào (In-degree) của một đỉnh $v$ trên Đồ thị có hướng biểu diễn bằng Ma trận kề.
  • Level 4 (Exam Style): So sánh độ phức tạp thời gian và điều kiện áp dụng của Dijkstra, Bellman-Ford, và Floyd-Warshall.
  • Level 5 (Challenge): Phát hiện chu trình âm (Negative Cycle) trong đồ thị bằng cách chạy thêm 1 vòng lặp relaxation thứ $V$ trong thuật toán Bellman-Ford.

4. Exam Simulator (Thi Thử Cuối Kỳ)

Câu 1 (2.5 điểm): Sắp Xếp & Đếm Phép Toán

Cho dãy số $A = [25, 12, 40, 8, 30]$.

a) Trình bày trạng thái mảng sau từng bước của Interchange Sort. Tính số phép so sánh $C$ và số phép đổi chỗ $M$.

b) Thực hiện phân hoạch Lomuto đầu tiên cho Quick Sort với Pivot $a[high] = 30$.

Lời giải tóm tắt:
a) $C = 5(4)/2 = 10$ phép so sánh. Trạng thái sau từng i:
• $i=0$: Swap(25, 12) $\Rightarrow$ Swap(12, 8) $\Rightarrow [8, 25, 40, 12, 30]$
• $i=1$: Swap(25, 12) $\Rightarrow [8, 12, 40, 25, 30]$
• $i=2$: Swap(40, 25) $\Rightarrow [8, 12, 25, 40, 30]$
• $i=3$: Swap(40, 30) $\Rightarrow [8, 12, 25, 30, 40]$. Mảng hoàn chỉnh! Total Swaps $M = 5$.

Câu 2 (2.5 điểm): Cây AVL

Lần lượt chèn các khóa sau vào cây AVL rỗng: $30, 20, 40, 10, 5$. Xác định nút mất cân bằng và vẽ cây AVL sau mỗi lần xoay.

Lời giải tóm tắt:
• Chèn 30, 20, 40 $\Rightarrow$ Cây cân bằng hoàn hảo ($BF(30) = 0$).
• Chèn 10 $\Rightarrow$ Vẫn cân bằng ($BF(30) = +1, BF(20) = +1$).
• Chèn 5 $\Rightarrow$ Mất cân bằng LL tại nút 20 ($BF(20) = +2, BF(10) = +1$).
• Xoay Phải (Rotate Right) tại nút 20 $\Rightarrow$ Nút 10 lên làm cha của 5 và 20.
• Cây AVL hoàn chỉnh sau xoay: Gốc 30, Cây con trái là 10 (con trái 5, con phải 20), Cây con phải là 40 ($BF(30) = +1$, tất cả các nút $|BF| \le 1$).

Câu 3 (2.5 điểm): Bảng Băm & B-Tree

Cho $M=7, h(k) = k \bmod 7$. Chèn các khóa $14, 21, 7, 15$ dùng Linear Probing. Tính $C_{\text{succ}}$ trung bình.

Lời giải tóm tắt:
• 14 % 7 = 0 $\Rightarrow$ Ô 0 (1 probe)
• 21 % 7 = 0 $\Rightarrow$ Ô 1 (2 probes)
• 7 % 7 = 0 $\Rightarrow$ Ô 2 (3 probes)
• 15 % 7 = 1 $\Rightarrow$ Đụng ô 1 $\Rightarrow$ Ô 3 (3 probes)
$\Rightarrow C_{\text{succ}} = \frac{1 + 2 + 3 + 3}{4} = \frac{9}{4} = 2.25$ phép so sánh.

Câu 4 (2.5 điểm): Đồ thị Dijkstra

Lập bảng trace Dijkstra tìm đường đi ngắn nhất từ đỉnh 0 cho đồ thị 4 đỉnh với ma trận trọng số cho trước.
